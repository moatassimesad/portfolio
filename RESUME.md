# Editing the Résumé & Generating the PDF

The résumé is a single self-contained HTML file styled for A4 print. Each
served PDF is just that HTML printed to PDF — there is no build step or script,
so the PDF must be regenerated by hand after any edit. There are two language
versions (English + French) kept in sync.

## Files

| File | Role |
|------|------|
| [resume.html](resume.html) | English source. Content + all styling (inline `<style>`). Edit this. |
| [MOATASSIME_SAAD_RESUME_EN.pdf](MOATASSIME_SAAD_RESUME_EN.pdf) | Exported English PDF served by the site. Regenerate after editing `resume.html`. |
| [resume-fr.html](resume-fr.html) | French source. Same layout/styling as the English one; only the text differs. |
| [MOATASSIME_SAAD_RESUME_FR.pdf](MOATASSIME_SAAD_RESUME_FR.pdf) | Exported French PDF served by the site. Regenerate after editing `resume-fr.html`. |
| [assets/images/saad.jpg](assets/images/saad.jpg) | The header photo referenced by both HTML files. |
| [index.html](index.html) | Resume button opens a language picker that links to the two PDFs above. |

## File / download naming (keep consistent)

The PDF filenames encode the name + language, in uppercase:

- English → `MOATASSIME_SAAD_RESUME_EN.pdf`
- French  → `MOATASSIME_SAAD_RESUME_FR.pdf`

These are both the **on-disk filenames** and the **download names**. In
`index.html` the picker cards carry the filename in `data-resume-file`, and the
download handler sets `download` to that same filename, so a saved file matches
exactly what's on disk:

```html
<button class="rp-card" data-resume-file="MOATASSIME_SAAD_RESUME_EN.pdf">…</button>
<button class="rp-card" data-resume-file="MOATASSIME_SAAD_RESUME_FR.pdf">…</button>
```

If you rename a PDF, update its `data-resume-file` value in the picker to match.

## Editing the résumé

1. Open [resume.html](resume.html) (or [resume-fr.html](resume-fr.html) for French).
2. Edit the content directly in the markup:
   - **Header** — name, headline, contact links: the `<header>` block (~line 92).
   - **Summary** — the `<p class="summary">` paragraph.
   - **Experience** — each role is a `<div class="entry">`. Copy an existing
     entry to add a new one; keep the same structure:
     - `.entry-title` → role + `.co` (company), location
     - `.entry-date` → dates, optional `.site` link
     - `<ul><li>…</li></ul>` → bullet points
     - `.tech` → `<span class="chip">…</span>` tags
   - **Education / Skills / Languages / Interests** — the remaining `<section>`s.
3. Styling lives in the `:root` variables and `<style>` block at the top
   (colors, font sizes, spacing). The font sizes are deliberately small (≈10px)
   so everything fits on **one A4 page** — watch the page length when adding
   content. (The French version uses slightly tighter print sizing because the
   text runs longer.)
4. Keep both language versions in sync when you change shared facts.
5. Preview by opening the HTML in a browser. Use the browser's print preview
   (Cmd+P) to see exactly how it will paginate.

### Keeping it to one page
- The print rules live in `@media print` and `@page{ margin:0; size:A4; }`.
- `.entry{ break-inside:avoid; }` keeps a single job from splitting across pages.
- If content overflows, trim bullets or nudge the font sizes / margins down
  slightly rather than letting it spill onto a second page.

## Generating the PDFs from the HTML

Goal: produce A4, single-page PDFs with backgrounds/colors intact (the chips and
accent rules use `print-color-adjust:exact`, already set in the HTML).

### Headless Chrome (repeatable, command line)
```bash
# macOS — adjust the path/flags to your Chrome install
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="MOATASSIME_SAAD_RESUME_EN.pdf" "file://$PWD/resume.html"

"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --no-pdf-header-footer \
  --print-to-pdf="MOATASSIME_SAAD_RESUME_FR.pdf" "file://$PWD/resume-fr.html"
```
Page size (A4) and zero margins come from the `@page` rule already in the HTML.

### Browser (no tooling)
1. Open the HTML in Chrome → Cmd+P → **Destination: Save as PDF**.
2. Paper size **A4**, Margins **None**, **Background graphics: ON**.
3. Save over the matching `MOATASSIME_SAAD_RESUME_*.pdf` in the project root.

## After regenerating

1. Confirm each result is **1 page**:
   ```bash
   file MOATASSIME_SAAD_RESUME_EN.pdf MOATASSIME_SAAD_RESUME_FR.pdf
   # → each: "PDF document … 1 pages"
   ```
2. Open the PDFs to eyeball colors, photo, and layout.
3. Commit the HTML and its PDF together so the served PDF matches the source:
   ```bash
   git add resume.html resume-fr.html MOATASSIME_SAAD_RESUME_EN.pdf MOATASSIME_SAAD_RESUME_FR.pdf
   git commit -m "Update résumé"
   ```
